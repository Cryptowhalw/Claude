# Архитектура коммерческой версии (подписки для мастеров)

Цель: продавать доступ к программе другим сервис-центрам по подписке.
Десктоп-`.exe` сам по себе не защищается — защита строится на **онлайн-активации**.

```
┌────────────────────────┐        HTTPS (JSON)        ┌──────────────────────────┐
│  Клиент (WPF, у мастера)│  ───────────────────────▶ │  Сервер лицензий (твой)   │
│                        │  activate / validate       │  ASP.NET + БД + биллинг    │
│  - диагностика ADB     │ ◀───────────────────────   │                           │
│  - платные функции     │   подписанный ответ        │  - ключи и подписки        │
│    (за замком лицензии)│   (Ed25519 + срок)         │  - привязка к железу (HWID)│
└────────────────────────┘                            │  - платежи (ЮKassa/Stripe) │
                                                       └──────────────────────────┘
```

## 1. Модель подписки
- **Ключ активации** (напр. `MSP-XXXX-XXXX-XXXX`) выдаётся после оплаты.
- Ключ привязывается к **HWID** (отпечаток железа: диск+материнка+CPU),
  лимит N активаций на ключ.
- Срок действия: месяц/год. Клиент хранит кэш лицензии и работает оффлайн
  до `grace_period` (напр. 3–7 дней), затем требует повторной проверки.

## 2. Защита ответа сервера
- Сервер подписывает лицензию приватным ключом **Ed25519**; публичный ключ
  зашит в клиент. Клиент проверяет подпись — ответ нельзя подделать прокси.
- В лицензию входят: `license_id`, `hwid`, `plan`, `features[]`, `expires_at`,
  `nonce`, `signature`. Проверяется срок + совпадение HWID.
- Платные функции вызываются только при валидной подписи и неистёкшем сроке.

## 3. Сервер (рекомендация)
- ASP.NET Core Minimal API + PostgreSQL (или SQLite на старте).
- Эндпоинты: `POST /activate`, `POST /validate`, `POST /deactivate`,
  админ-панель для выпуска/блокировки ключей.
- Биллинг: webhook от платёжной системы → создание/продление подписки.
- Логи активаций и анти-фрод (один HWID — много ключей, резкий рост активаций).

## 4. Что защищать замком лицензии
Диагностику можно оставить бесплатной (приманка), а за подписку — отчёты,
каталог драйверов, прошивку, пакетные операции, облачную историю ремонтов.

## 5. Честные ограничения
- Любой десктоп-клиент можно вскрыть; цель защиты — сделать это дороже выгоды
  и быстро отзывать утёкшие ключи через сервер.
- Для оплаты и обработки данных клиентов нужны юрлицо/самозанятость, оферта и
  политика конфиденциальности (ПДн).

## Следующий шаг реализации
1. `LicenseClient.cs` в клиенте: HWID, вызовы activate/validate, проверка Ed25519,
   кэш лицензии, гейт функций (`FeatureGate`).
2. Отдельный проект `MobileServicePro.LicenseServer` (ASP.NET Core).
